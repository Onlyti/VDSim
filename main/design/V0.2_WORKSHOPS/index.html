    v0.2 — component workshops (WS2, design for review)¶

    Status: design draft (2026-06-05), pending review. Builds on WS1 (subsystem modules

    159-162 + deadtime). Multi-vehicle (#157/#158) is deferred to the end of v0.2.0.¶

    Goal¶

    A per-subsystem workshop in the GUI: edit a component's parameters, see the relevant curve, import vendor data where applicable, and pick from a sample library. Each workshop drives the WS1 module params, so edits change the running plant. This is the "compose a vehicle from parts" UX for the parameters.

    Existing infrastructure (reuse)¶

    • GUI "Plant (vehicle · tire · actuator)" builder window (gui/index.html win_plant/plant_body) + live param edit via POST /api/vehicle|tire|actuator| sensors -> Runner.set_params (re-applies to the live plant).
    • GET /api/tire/curves (tire curve data), /api/actuator/step (step response).
    • .tir import already exists at lib level: python/tir_to_yaml.py + TireParams::from_tir — needs a GUI entry point + a sample library.

    Prerequisite gap (do first)¶

    Deadtime is not configurable yet. The default modules are built with deadtime_s = 0 (factory default); VehicleParams has no deadtime fields, and the dynamics construct the modules without passing one. Workshops that edit deadtime need: - add brake_deadtime_s, steer_deadtime_s, drive_deadtime_s to VehicleParams (+ YAML, default 0); - seven_dof constructs make_default_* with those values; - expose in /api/vehicle set_params + the workshop UI. This is a small WS1/WS2 bridge — call it WS2-0.

    Workshops (scope + priority)¶

    # Workshop Edits (params, all already in VehicleParams unless noted) Viz / import
    WS2-0 deadtime bridge NEW brake/steer/drive deadtime_s — (config plumbing)
    WS2-1 Suspension spring_stiffness[4], damper_coefficient[4], arb_stiffness_front/rear + level presets rate curve; soft/med/stiff samples
    WS2-2 Brake max_brake_torque, brake_bias_front, brake_ebd_enabled, brake_deadtime_s brake torque vs pedal (+per-wheel)
    WS2-3 Steering steering_ratio, steer_deadtime_s, unity toggle road-wheel vs handwheel
    WS2-4 Drivetrain max_motor_torque, final_drive_ratio, differential, lsd_preload/ramp, drive_deadtime_s axle/wheel torque split
    WS2-5 Tire .tir import (wire tir_to_yaml/from_tir) + sample library reuse /api/tire/curves
    WS2-6 Engine map (torque-RPM / efficiency) UI stub only model is v0.3 (V0.2_DRIVETRAIN)

    Recommended order: WS2-0 (bridge) -> WS2-1 (suspension; all params exist, ARB now functional, self-contained) -> WS2-⅔/4 (brake/steer/drivetrain, share the bridge) -> WS2-5 (tire import) -> WS2-6 (engine stub, finished in v0.3).

    Per-workshop pattern¶

    • A collapsible panel (extend win_plant or a new "Workshops" window) with the param fields, a small plot canvas for the curve, and (where relevant) an Import button + a sample dropdown.
    • Edits POST to the existing set_params endpoints (add fields, e.g. the new deadtime / arb keys); the runner re-applies to the live plant.
    • Samples = small YAML snippets under configs/components/<type>/*.yaml.

    Decisions (2026-06-05)¶

    1. New dedicated "Workshops" window, UI freshly designed (user). Not bolted onto the existing win_plant builder. Layout: a left vertical subsystem selector (Suspension / Brake / Steering / Drivetrain / Tire / Engine), right pane = the selected workshop's param editor + a curve canvas + (where relevant) Import + sample dropdown. A small status line shows "applied to live plant".
    2. Samples: configs/components/<type>/*.yaml snippets (consistent with configs).
    3. Curve plotting: one shared small canvas plot helper, reused by every workshop.
    4. Delegation: the Workshops window UI (HTML/CSS/JS) is GUI boilerplate -> Cursor (composer-2.5); the set_params field additions + any core/params wiring -> Claude-reviewed. WS2-0 deadtime bridge (core) is DONE (aa4fca7).
    5. Build order: WS2-0 (done) -> new Workshops window shell + Suspension tab (first real workshop, all params exist) -> Brake/Steering/Drivetrain tabs (use the deadtime fields) -> Tire (wire .tir import + samples) -> Engine (stub, v0.3).

    Workshops window — UI spec (for the scaffold)¶

    • Toolbar button "Workshops" opens a draggable window win_workshops (like the existing win_plant), ~720x460, white panel, accent #01A0E9.
    • Left column: subsystem list (buttons), active item highlighted.
    • Right column (per active subsystem): a form of labelled number inputs bound to the vehicle params (live POST to /api/vehicle on change, debounced), a <canvas> for the characteristic curve, and Import/sample controls where listed.
    • Suspension tab (first): per-corner spring_stiffness[4], damper_coefficient[4]; arb_stiffness_front/rear; a "level" preset dropdown (soft/med/stiff) that fills the fields; curve = force vs deflection for the selected corner. Sample snippets from configs/components/suspension/*.yaml.

    Relationship¶

    • WS1 (V0.2_SUBSYSTEMS.md) = the modules these workshops edit.
    • WS4 (parts assembly) and WS3 (scene UI) come after; multi-vehicle last.
