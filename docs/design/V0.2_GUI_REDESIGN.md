# v0.2 — GUI full redesign (WS3 + WS4 + WS2 shell)

Status: design (2026-06-05), user art-directed. Replaces the bolt-on Workshops
window (e7d47d1) with a full-screen app centred on a vehicle tree.

## Decisions (user)

- **Brand-new full-screen frame** (not the current 3D-centric index.html chrome).
- Left vertical sidebar stack: **SIM controls (top) -> vehicle+sensor tree (mid) ->
  mini-map (bottom)**.
- Add / edit / delete vehicles; sensors nested under each vehicle; an "infra/ground"
  sensor group (sensors not on a vehicle).
- **[Edit vehicle] opens a large separate modal/panel** to manage that vehicle's
  modules (the component workshops).
- Build as a NEW page `gui/app.html` so the working `index.html` is untouched (no
  regression); once approved it becomes the default. Reuse the existing three.js
  scene + SSE state stream + `/api/*` endpoints.

## Layout (full screen — 3 columns, NO top tabs)

The top tabs are dropped (no need). Right column = the selected vehicle's live
telemetry.

## Data wiring (reuse existing endpoints)

- SIM controls: play/stop/reset -> `POST /api/control {action}`; realtime slider ->
  `POST /api/sim {time_scale}`; save/load -> new small `/api/simconfig` (later).
- Vehicle tree: vehicles + their sensors. NOTE the live runtime is single-vehicle
  today (multi-vehicle runtime = #157, last of v0.2.0). So v1: show the one live
  vehicle + its sensors (from `/api/sensors`), with add/infra stubbed/disabled and a
  tooltip "multi-vehicle: pending #157". Tree is built so #157 just populates it.
- Module modal: tabs reuse the field rows from `GET /api/vehicle` grouped per
  subsystem (Suspension/Drivetrain->Brake+Drivetrain/Steering) + tire from
  `/api/tire` + sensors from `/api/sensors`; live edits POST as today; curves reuse
  the existing plot helper; tire .tir import + presets per `V0.2_WORKSHOPS.md`.
- Mini-map: a `<canvas>` plotting vehicle (x,y) from the SSE state stream.
- three.js scene + control (keyboard/manual) + SSE: reuse from index.html.

## Build approach

- `gui/app.html`: new full-screen layout. Factor the reusable JS (scene init, SSE,
  api helpers, field rendering) so both pages can use it (extract to `gui/app.js`
  or import from a shared module) WITHOUT breaking index.html.
- Server: add a route to serve `/app` (or `app.html`) alongside `/`.
- The standalone Workshops window in index.html (e7d47d1) is superseded -> remove or
  leave dormant once app.html lands.

## Sequence

1. app.html shell: sidebar (SIM controls + vehicle tree skeleton + mini-map) +
   center 3D view, served at `/app`. (layout + scene reuse)
2. Module modal with the subsystem tabs (reuse workshop param/curve logic).
3. Tire .tir import + samples; SIM save/load; infra-sensor group.
4. (later) multi-vehicle tree populated by #157.

## Verification note

GUI cannot be visually verified in the agent environment (no browser/JS engine).
Each step: confirm it serves + structural checks; the user does the visual review
and iterates.
